# Noise Gate for a Voice-Native Agent — Research Brief (October 2026)

> Produced by a deep-research agent 2026-10-20; synthesized for the osborn noise-gate design.
> Scope: a triage layer that sees every transcript utterance before the agent, decides
> drop / forward-verbatim / ask-or-hold, with conversational context, batching, and a toggle.

## 1. How voice-agent stacks handle turn detection, noise, and side-speech (2025–2026)

**LiveKit Agents** — five `turn_detection` modes on `AgentSession`: turn-detector model (default), `vad`, `stt` (STT endpointing, e.g. Deepgram Flux/AssemblyAI), `realtime_llm`, `manual` (https://docs.livekit.io/agents/build/turns/). The current **Turn Detector v1.0** (blog June 17, 2026) is **audio-native** — parallel semantic + acoustic (prosody) branches, no transcript dependency, 14 languages; `v1` runs on LiveKit Inference (free on Cloud), `v1-mini` is open-weight and runs locally on CPU (https://livekit.com/blog/solving-end-of-turn-detection). The older **text-based EOU model (Qwen2.5-0.5B, INT8 ONNX, ~50–160 ms CPU)** is deprecated, removal slated for SDK 2.0 (https://docs.livekit.io/agents/build/turns/turn-detector/, https://huggingface.co/livekit/turn-detector) — notable because it's a proven recipe for a cheap local text classifier over recent turns. Noise handling: Krisp **NC** (noise only, free on Cloud), **Krisp VIVA voice isolation** (removes *competing voices*, keeps primary speaker — Cloud-only, extra cost), plus ai-coustics Voice Focus (only self-host path, BYO key) (https://docs.livekit.io/transport/media/noise-cancellation/). Side-speech mitigation beyond that: `interruption.mode: "adaptive"` (backchannel vs. real interruption) and `false_interruption_timeout` + `resume_false_interruption` — agent auto-resumes after a barge-in that produced no transcript. **No addressee detection.**

**Pipecat (Daily)** — **Smart Turn v3** (Sept 11, 2025): Whisper-Tiny encoder + linear head, ~8M params, 8 MB int8 ONNX, 23 languages, ~12 ms CPU inference; fully open source (BSD-2, weights + training data) (https://github.com/pipecat-ai/smart-turn, https://www.daily.co/blog/announcing-smart-turn-v3-with-cpu-inference-in-just-12ms/); v3.2 adds noisy-environment handling. Pipecat 1.0 (Apr 2026) replaced `interruption_strategies` with `user_turn_strategies`: `MinWordsUserTurnStartStrategy`, **`WakePhraseUserTurnStartStrategy`** (closest built-in to addressee gating), `KrispVivaIPUserTurnStartStrategy` (Krisp Interruption Prediction: backchannel vs. genuine interruption), `EagerUserTurnStopStrategy` (speculative response + withdrawal) (https://docs.pipecat.ai/api-reference/server/utilities/turn-management/user-turn-strategies). `KrispVivaFilter` as `audio_in_filter` (BYO `KRISP_VIVA_API_KEY`) (https://docs.pipecat.ai/pipecat/features/krisp-viva). **No addressee detection.**

**OpenAI Realtime** — `turn_detection`: `server_vad` (threshold / prefix_padding_ms / silence_duration_ms) or `semantic_vad` with `eagerness` low/medium/high/auto (shipped March 2025; GA + `gpt-realtime` Aug 28, 2025); `input_audio_noise_reduction: near_field|far_field` (https://developers.openai.com/api/docs/guides/realtime-vad). **No side-speech feature** — OpenAI's own prompting guide recommends a no-op tool pattern: "If the latest audio is… side conversation or speech not addressed to you, call `wait_for_user`" and say nothing (https://developers.openai.com/api/docs/guides/realtime-models-prompting). Community threads document background chatter and transients breaking sessions, and a pathological latency bug combining noise reduction + semantic_vad (https://community.openai.com/t/realtime-api-with-noise-reduction-has-sudden-increase-of-latency/1256390).

**Across all three: nobody ships "is this utterance for me?"** The one third-party exception: **Attention Labs SAA SDK** (verified: https://github.com/attenlabs/saa-sdk) — hosted WebSocket addressee classifier running *before* STT, per-utterance device-directed decision, filters side talk / ambient media / agent's own TTS echo; drop-in clients for LiveKit, Pipecat, ElevenLabs, Twilio; Apache-2.0 clients, proprietary hosted inference (on-device = enterprise license); claims 0.86 F1 audio-only / 0.95 with video. No public pricing.

> **For osborn:** the gate doesn't exist off-the-shelf in any major framework — a real gap; the one startup in the space (Attention Labs) validates the "classifier in front of the agent" shape. Borrow LiveKit's `false_interruption_timeout`/resume pattern and OpenAI's no-op-tool prompt trick as cheap complements.

## 2. Speaker recognition: can an STT provider tag MY voice?

**Yes — exactly one major STT does it natively: Speechmatics.** Realtime speaker identification with enrollment: enroll from a 5–30 s solo clip in a diarization session with `"get_speakers": true` (or a `GetSpeakers` message) → store the string `speaker_identifiers` → in later realtime sessions pass `speaker_diarization_config.speakers: [{label: "Osborn", speaker_identifiers: [...]}]`; your words get tagged `Osborn`, strangers stay S1/S2. Caps: 50 identifiers/session; identifiers are model-bound (re-enroll on model change). Realtime pricing $0.30–0.45/hr, ID apparently included (https://docs.speechmatics.com/speech-to-text/features/speaker-identification, https://docs.speechmatics.com/speech-to-text/realtime/speaker-identification, https://www.speechmatics.com/pricing).

**Everyone else:** Deepgram — streaming diarization only (anonymous clustering, no enrollment; and **Flux has no diarization at all**, only Nova-3 on v1) (https://developers.deepgram.com/docs/diarization). AssemblyAI — streaming diarization beta (+$0.12/hr); its "Speaker Identification" is LLM name/role inference, **not** voiceprints, async-only (https://www.assemblyai.com/docs/speech-understanding/speaker-identification). Gladia — no live diarization at all. **The hyperscalers exited voice biometrics**: Azure Speaker Recognition retired Sept 30, 2025 (SDK 1.47 removed it); AWS Connect Voice ID end-of-support May 20, 2026 (AWS points to Pindrop); Google Speaker ID docs 404 (https://docs.aws.amazon.com/connect/latest/adminguide/amazonconnect-voiceid-end-of-support.html).

**Edge/on-device options:** **Picovoice Eagle** — on-device streaming speaker recognition, few-second enrollment, 4.5 MB model, frame-by-frame scoring, Pi-class capable; vendor EER 0.18% (VoxConverse, not comparable to VoxCeleb numbers); Foundation plan $6,000/**yr** (startups only, 10K min/mo); the 100 min/mo free tier was reportedly sunset after June 30, 2026 (third-party; primary page JS-gated) (https://github.com/Picovoice/eagle). **Open source**: CAM++ (3D-Speaker) is the best accuracy/CPU ratio — 7.18M params, 0.65% EER VoxCeleb1-O, RTF 0.013 single-thread → ~26 ms to embed a 2 s window (https://arxiv.org/pdf/2303.00332); ECAPA-TDNN 0.80% EER (https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb); TitaNet-large 0.66% (https://huggingface.co/nvidia/speakerverification_en_titanet_large); **sherpa-onnx** packages these as ONNX with mobile demos — easiest fully-offline path (https://github.com/k2-fsa/sherpa-onnx). **pyannoteAI** hosted API has true voiceprint enroll + identify (€0.096/hr, €0.015/voiceprint) but identification is **batch-only**; its Live-1 streaming diarization doesn't do voiceprint matching yet (https://docs.pyannote.ai/models, https://www.pyannote.ai/pricing).

**Reality checks:** verification degrades hard under ~2 s of speech (EER multiplies 2–5×); enroll/verify **channel mismatch is the silent killer** — enroll on the same earpiece mic you'll verify on; aggregate scores over ≥2 s of voiced speech; calibrate the threshold per-device (AS-Norm or DIY calibration) (https://arxiv.org/abs/1810.10884, https://arxiv.org/abs/2608.17972).

> **For osborn:** speaker-ID is the highest-precision "drop strangers" signal and it's cheap — either switch/add Speechmatics for native tagged words, or keep the current STT and bolt on a CAM++/sherpa-onnx embedding check (~30 ms CPU per utterance, $0). Enroll per-device; treat sub-2s utterances as "speaker unknown," not "not you."

## 3. Audio-level noise suppression (the layer below)

- **RNNoise** (2017, Xiph): ~88k weights, ~40 MFLOPS, runs on a Pi; removes non-speech noise only — a second talker is speech and is *preserved* (https://github.com/xiph/rnnoise).
- **DeepFilterNet v3**: open source, real-time on CPU (RTF ≈ 0.19 on an i5-8250U), LADSPA plugin; same limitation — trained to preserve all speech (https://github.com/rikorose/deepfilternet). (SEO blogs claiming it handles overlapping speech are wrong.)
- **Krisp** is the only commercial "remove other talkers" option: **BVC**/`Voice Isolation v3` under **VIVA 2.0** (May 6, 2026: ~15 ms latency, ~30 MB, CPU server-side; plus Turn Prediction v3 and Interruption Prediction v1) (https://krisp.ai/blog/viva-2-0-ai-infrastructure-for-voice-ai-agents/). Critical caveat: "primary speaker" is **proximity/dominance-based, not enrollment-based** — docs require the user within ~30 cm of the mic, admit secondary-voice leakage after device switches, and the far-field model drops voice removal entirely (https://sdk-docs.krisp.ai/docs/models-for-conversational-ai). Via **LiveKit Cloud only** (self-hosted SFU can't use Krisp models; ai-coustics is the self-host alternative) or via Pipecat's `KrispVivaFilter`; also a cloud WebSocket API (`wss://streaming.krisp.ai/voice-isolation`). Sales-gated pricing.
- **Apple Voice Isolation**: iOS 15+/macOS 12+ mic mode; **user-toggled only** — `AVCaptureDevice.preferredMicrophoneMode` is read-only, apps can only pop Control Center via `showSystemUserInterface(.microphoneModes)`. AirPods Voice Isolation (H2, iOS 18) cleans the transmitted voice; dominance-based, not identity-based.
- **True target-speaker extraction** (condition on an enrolled embedding — Google VoiceFilter-Lite, Microsoft pDNS/Teams voice isolation, NTT SpeakerBeam-SS) exists in research and inside walled products, but **no self-serve developer SDK ships it in 2026**.

> **For osborn:** audio cleanup is worth having (Krisp VIVA via LiveKit Cloud, or free DeepFilterNet if self-hosting) because it cuts ghost transcripts and false VAD triggers — but in an earpiece-in-public scenario where strangers can be as loud as the user, it **cannot** be the gate; dominance-based isolation leaks exactly the speech that must be filtered. The gate lives at the transcript/semantic layer.

## 4. The semantic gate pattern: device-directed speech detection (DDSD)

The academic term is **"device-directed speech detection"** / addressee detection; Apple dominates 2024–2026 publications. Converged recipe: fuse (a) acoustic encoder features, (b) ASR 1-best text, (c) ASR decoder uncertainty signals, (d) **prior-turn context**, into an LLM with LoRA; distill for on-device. Key papers: Apple multimodal DDSD w/ LLMs, ICASSP 2024 — multimodal beats text-only by up to 39% rel. EER (https://arxiv.org/abs/2403.14438); Apple **follow-up conversations** DDSD, NeurIPS 2024 workshop — conditioning on the *first query* cuts false alarms 20–40% at fixed 10% false-reject (https://arxiv.org/abs/2411.00023); SELMA, ICASSP 2025 (https://arxiv.org/abs/2501.19377); **SAS paper, Apr 2026** — reframes DDSD as sequential routing over interaction history: audio-only F1 0.86; removing history drops F1 to 0.57 — **conversational context is the load-bearing signal** — <150 ms, <20 MB on ARM (https://arxiv.org/abs/2604.08412).

Shipped systems: **Alexa Follow-Up Mode** reopens the mic for 5 s post-response with an audio DDSD gate; **Alexa Conversation Mode** adds camera-based gaze gating. **Google Continued Conversation is effectively dead** — killed in the Gemini transition; wake-wordless follow-up now paywalled behind Google Home Premium. Siri still has no general wake-wordless attention. **Limitless pendant** records everything, no gating. **No canonical open-source "small LLM classifies addressed-to-assistant" repo exists** — the pattern lives in Apple's papers and Attention Labs' closed product; the ecosystem gap is real.

> **For osborn:** the research unanimously says the gate needs three inputs, not one: the verbatim transcript, the speaker-ID score, and **the recent agent/user conversation context** (its absence halves F1). A 20 MB-class model achieves <150 ms in the literature, so a fast-brain LLM call or a distilled local classifier are both in-budget. Apple's "false-reject is costlier than false-accept" framing maps directly to the ambiguous→ask bucket.

## 5. Batching / turn semantics and never losing real speech

Canonical streaming semantics (Deepgram, generalizes): `is_final` = segment transcript frozen (accuracy-final, NOT turn-final); `speech_final` = endpointing fired. **Correct pattern: buffer `is_final` segments, flush on `speech_final`**, with `utterance_end_ms` (word-gap timer) as a backstop when background noise suppresses `speech_final` (https://developers.deepgram.com/docs/understand-endpointing-interim-results). Endpointing defaults are chatbot-fast (10 ms); 300–500 ms recommended for conversation. **Deepgram Flux** (Sept 2025) moves turn detection into the STT model: continuous end-of-turn probability, ~260 ms P50 EOT, and **eager mode** — `EagerEndOfTurn` starts speculative downstream work, `TurnResumed` cancels it (https://deepgram.com/learn/introducing-flux-conversational-speech-recognition). LiveKit's `preemptive_generation` and Pipecat's `EagerUserTurnStopStrategy` are the same **forward-with-confidence + late-retract** pattern. The verbatim-retention insight: these systems never *reword* — they only decide *when to cut* — and the retract primitive (cancel speculative work, keep the buffer) is exactly what lets a gate be aggressive without losing speech.

> **For osborn:** accumulate interim transcripts per turn, flush to the gate on endpoint/EOT; never discard a buffer on "drop" — tombstone it (visible, recoverable, "send anyway" tap) so a false drop costs one tap, not lost words. For ambiguous-forwarded utterances, adopt the Flux pattern: forward eagerly, retract/supersede if the next utterance reveals it was side-talk and the agent hasn't acted yet.

## 6. Recommended architecture

**Where the gate sits:** between STT output and the agent router — per-utterance pipeline: `[optional audio cleanup] → STT (+speaker tag) → GATE → agent`. Three stacked signals, cheapest-first:

1. **Speaker gate (near-free, high precision):** enrolled-voice check. Either Speechmatics realtime speaker ID (native, $0.30–0.45/hr total STT) or a local CAM++/sherpa-onnx embedding per utterance (~30 ms CPU, $0). Not-you + not-ambiguous → drop before any LLM spend. Enroll per-device; sub-2s utterances fall through to the semantic gate rather than hard-dropping.
2. **Semantic gate (fast-brain tier):** nano-tier LLM classifies `{directed | side_talk | ambiguous}` given the verbatim utterance + rolling context (last N user/agent turns + current task summary) + the speaker score. Cached system prompt. ~500 in / ~10 out tokens. Output is a label only — **the forwarded payload is always the untouched transcript**. gpt-5-nano ($0.05/$0.40 per MTok), Gemini 2.5 Flash-Lite ($0.10/$0.40), or Haiku-class with prompt caching all land at **$0.02–0.06/hr of active speech**.
3. **Ambiguity UX:** if agent is silent → one short spoken prompt ("send that to the agent?") with a ~5 s accept window (Alexa Follow-Up's exact shape); if agent is speaking → hold in a visible "held utterances" tray, never auto-drop. Rate-limit confirmations; let repeated confirms/denies tune the threshold.

**Toggle & cost:** always-on cost is **dominated by STT, not the gate**: Deepgram Nova-3 $0.29–0.46/hr, Speechmatics $0.30–0.45/hr, AssemblyAI $0.15/hr (billed on **session time**, not audio time — decisive for an always-open ambient socket) + nano-LLM $0.02–0.06/hr → **roughly $0.35–0.55 per ambient hour**, ~$3–4 for an 8-hour day. Justifies the toggle: a dedicated gate button, implied-on by meeting mode, and client-side VAD (Silero, free, local) so silence never opens the STT/session meter.

**Buy vs build:** build the gate (a prompt + plumbing; no off-the-shelf product except Attention Labs — pre-STT audio-domain, unpriced, awkward under the verbatim-transcript requirement; worth a trial as a comparison baseline, not a dependency). Buy speaker-ID (Speechmatics) or self-host it (sherpa-onnx + CAM++). Optionally buy Krisp VIVA via LiveKit Cloud as hygiene, never as the gate. Later optimization: distill the LLM gate into a local DistilBERT/Qwen-0.5B-class classifier (LiveKit's deprecated EOU model proves 0.5B INT8 ONNX does 50–160 ms on CPU) to take marginal cost to zero.
